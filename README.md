# Introduction
Educational institutions contain many shared spaces and high-traffic areas. Students move between classrooms, laboratories, libraries, cafeterias, sports facilities, transport points, and administrative blocks. Personal belongings can be misplaced in any of these locations. When an item is found by another person, the owner may not know where to look for it. Similarly, a person who finds an item may not know how to identify or contact its owner.
In many college environments, lost-and-found communication is handled informally. A student may post a message in a class group, ask friends, contact a faculty member, or visit an office. These methods can work for a small group, but information may be spread across multiple channels. Messages can be missed, older posts can become difficult to locate, and descriptions may not contain enough identifying details.
The need addressed by this project is therefore a centralized and structured reporting channel for lost and found belongings within a college context. The intended users are students and other members of the campus community who need to report an item or provide information about an item they have found. The portal organizes reports into a consistent set of fields and supports automated checking for possible matches.
The project is a prototype intended for academic demonstration. No campus-wide survey or verified institutional incident statistics were supplied for this report; consequently, no numerical claim is made about the frequency of lost items at Chandigarh University. The need is described as a practical use case rather than as a measured campus-wide finding.

# Problem Definition
The project aims to develop a web-based College Lost & Found Portal through which a campus user can submit details of a lost item or an item that has been found. The system should collect relevant item information in structured forms and send the report to a backend service. The backend should check the report against reports of the opposite type and return information indicating whether a possible match has been identified.
The project includes a home page, a Report Lost page, a Report Found page, navigation between these pages, form handling, backend API communication, and support for found-item image uploads. The scope does not include a verified campus identity system, payment processing, delivery or courier management, guaranteed ownership verification, or a full administrative dashboard unless these are added and tested separately.

# Result Analysis
The supplied screenshots demonstrate that the home page and the Report Found form have been implemented. The home page presents the portal's purpose and navigation, while the found-item form provides the fields needed to describe and report an item, including a photo.
The described frontend-to-backend workflow supports two different submission formats. JSON is used for lost reports, while multipart FormData is used for found reports with image upload. The backend-driven matching response provides a possible match status and score. Unmatched reports remain waiting.
The screenshots establish the appearance of the two displayed pages; they do not, by themselves, prove successful API submission, image storage, or matching accuracy. Those behaviors should be demonstrated through live tests and recorded in the test table. No numerical accuracy claim is made because a labelled test dataset and measured evaluation results were not supplied.
